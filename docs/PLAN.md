## 1. Technology decision

### 1.1 Constraint from the product owner

The product must be **Python-based with a C++ core**. This section justifies the concrete libraries within that constraint and records the measurements that shaped the architecture.

### 1.2 Measurements taken while planning (2-core Linux container, warm cache, single thread unless noted)

| Test                                                     | Pure Python                                                                                 | C++                            | Rust (reference)           |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------ | -------------------------- |
| Scan folders + read sizes, per 1M entries                | 2.4 s (`os.scandir`)                                                                        | 1.2–1.9 s (`openat`/`fstatat`) | 1.25–1.4 s (same syscalls) |
| Same scan with 8 Python threads                          | 3.4 s (GIL-bound, slower)                                                                   | scales with cores              | scales with cores          |
| MFT-style record parsing, per 1M records                 | 2.1 s (`struct`)                                                                            | 0.065 s                        | 0.064 s                    |
| Memory per tree node                                     | 276 B (objects with `__slots__`) / 90 B (NumPy arrays)                                      | 88 B design (§2.3)             | same                       |
| PySide6 `QTableView`, 10M-row model, jump-scroll repaint | median 15 ms, p95 22 ms with page cache + custom delegate (53 ms median with a naive model) | —                              | —                          |

Conclusions that drive the design:

1. **Everything per-file runs in C++** (enumeration, MFT parsing, tree storage, aggregation, sorting/filtering, treemap, hashing, snapshots, CSV/JSON export). Python never loops over all nodes in normal operation.
2. **Python owns orchestration and UX:** GUI, CLI, query parsing, HTML/PDF reports, scheduling, settings, delete/move planning.
3. The GUI's table must fetch **pages of rows** from C++ and paint with a **custom delegate**; a naive `QAbstractItemModel.data()` per role per cell is 3× too slow.
4. Speed difference between C++ and Rust is within noise; how the OS is called (directory-relative syscalls, batched Windows enumeration) matters more than language.

### 2.3 Core data model (C++, `core/include/dafree/model.hpp`)

Design goals: ≤ 100 bytes resident per node after scan, ≤ 140 bytes peak during a walk scan; no per-node heap allocation; children of a directory **contiguous**; `parent < child` for every node (single reverse pass aggregates).

```cpp
namespace dafree {

using NodeId = std::uint32_t;                 // max ~4.29 billion nodes per tree
inline constexpr NodeId kRoot = 0;            // synthetic root; children = scan targets
inline constexpr NodeId kNone = 0xFFFF'FFFFu;

enum NodeFlags : std::uint16_t {
    kDir            = 1u << 0,
    kSymlink        = 1u << 1,   // never descended unless follow_symlinks
    kReparse        = 1u << 2,   // Windows junction / other reparse point
    kMountPoint     = 1u << 3,   // filesystem boundary (not descended by default)
    kHardlinkDup    = 1u << 4,   // additional link of an already counted inode
    kHidden         = 1u << 5,
    kSystem         = 1u << 6,
    kAccessDenied   = 1u << 7,   // could not list (dir) or stat (file)
    kPartial        = 1u << 8,   // listing incomplete (error mid-enumeration / cancelled)
    kSparse         = 1u << 9,
    kCompressed     = 1u << 10,
    kCloudPlaceholder = 1u << 11,// OneDrive/iCloud dataless; never opened
    kExcluded       = 1u << 12,  // excluded/deleted; contributes nothing, hidden from views
    kError          = 1u << 13,
    kAllocUnreliable= 1u << 14,  // network FS / SFTP: allocated is an estimate
    kSynthetic      = 1u << 15,
};

struct Node {                    // 56 bytes, naturally aligned, no padding
    NodeId        parent;        // kNone for root
    NodeId        first_child;   // kNone if none
    std::uint32_t child_count;
    std::uint32_t name_off;      // offset into NameArena
    std::uint16_t name_len;      // bytes
    std::uint16_t flags;         // NodeFlags
    std::uint32_t ext_id;        // ExtInterner id, 0 = none
    std::uint64_t size;          // files: logical; dirs: aggregated
    std::uint64_t alloc;         // files: allocated; dirs: aggregated
    std::uint32_t mtime, btime, atime;   // A9
    std::uint32_t owner;         // OwnerTable id, 0 = unresolved
};
static_assert(sizeof(Node) == 56 && alignof(Node) == 8);
static_assert(std::is_trivially_copyable_v<Node>);

struct Counts { std::uint32_t files = 0, dirs = 0; };   // per node, below it (8 bytes)

// Segmented vector: 65,536 elements per segment; never reallocates existing segments
// (no 2x/3x copy spike on growth, stable references).
template <class T> class SegVector {
public:
    std::uint32_t push_back(const T& v);                         // throws CapacityError past UINT32_MAX
    std::pair<std::uint32_t, std::uint32_t> append(std::span<const T> vs); // [first, last) contiguous
    T& operator[](std::uint32_t i); const T& operator[](std::uint32_t i) const;
    std::uint32_t size() const noexcept;
    std::size_t heap_bytes() const noexcept;
    void shrink_last();                                           // trims last segment
    // Exposed to Python as read-only NumPy views per segment (see §2.9)
};

// Names as raw native bytes: UTF-8/arbitrary bytes on POSIX; WTF-8 on Windows
// (UTF-16 with possible lone surrogates, encoded losslessly). 1 MiB chunks; a name never spans chunks.
class NameArena {
public:
    std::pair<std::uint32_t, std::uint16_t> push(std::string_view native_bytes); // throws NameTooLong (>65535 B)
    std::string_view get(std::uint32_t off, std::uint16_t len) const;
    std::size_t heap_bytes() const noexcept;
};

class ExtInterner;   // lowercase extension → id (0 = none), ≤ 16 bytes, no spaces
class OwnerTable;    // id → display name; key = uid | SID bytes | remote string

struct ScanMeta {
    std::int64_t started_at = 0, finished_at = 0;   // unix seconds
    ScanModeUsed mode{};                            // Walk | Mft | Sftp
    ScanOptions options;                            // as used
    std::string host, os, app_version;
    std::vector<VolumeInfo> volumes;
    IssueSummary issues;                            // counts per kind + first 1,000 issues
    bool cancelled = false;
};

class Tree {
public:
    std::uint32_t size() const noexcept;
    const Node& node(NodeId) const;
    Counts counts(NodeId) const;
    std::string_view name_bytes(NodeId) const;              // root nodes: full root path
    std::optional<std::string_view> ext(NodeId) const;
    std::optional<std::string_view> owner_name(NodeId) const;
    std::pair<NodeId, NodeId> children(NodeId) const;       // [first, last)
    std::optional<NodeId> parent(NodeId) const;
    std::string path_bytes(NodeId) const;                   // native bytes, O(depth)
    std::uint16_t depth(NodeId) const;
    std::optional<NodeId> find_path(std::string_view native_path) const; // case-insensitive on Windows/macOS
    std::span<const NodeId> roots() const;
    MemoryReport memory_usage() const;
    void set_owner(NodeId, OwnerKey, std::string_view display);
    void mark_deleted(NodeId);                              // kExcluded + incremental re-aggregation
    void replace_subtree(NodeId at, const Tree& fresh, NodeId fresh_root); // O(n) rebuild, keeps invariants
    const ScanMeta& meta() const noexcept;
private:
    SegVector<Node> nodes_; SegVector<Counts> counts_; NameArena names_;
    ExtInterner exts_; OwnerTable owners_; std::vector<NodeId> roots_;
    std::vector<std::string> root_paths_; ScanMeta meta_;
};

class TreeBuilder {
public:
    explicit TreeBuilder(std::vector<std::string> root_paths); // creates kRoot + one node per root
    struct NewNode { std::string_view name; std::uint16_t flags; std::uint64_t size, alloc;
                     std::uint32_t mtime, btime, atime; std::optional<OwnerKey> owner; };
    // Appends all entries of `dir` contiguously; at most once per dir (throws AlreadyPopulated).
    std::pair<NodeId, NodeId> add_children(NodeId dir, std::span<const NewNode> entries);
    void mark(NodeId, std::uint16_t flags);
    void aggregate_partial();             // used for live progress (§2.3.1)
    Tree finish(ScanMeta meta) &&;        // aggregate + shrink
};
} // namespace dafree
```

#### 2.3.1 Aggregation (pseudocode, `core/src/model/aggregate.cpp`)

```text
fn aggregate(nodes, counts):
    for id in 0..len: if nodes[id].flags & kDir: nodes[id].size = nodes[id].alloc = 0; counts[id] = {0,0}
    for id in (1..len).reverse():                # parent < child ⇒ children done before parent
        n = nodes[id]; p = n.parent
        contributes = !(n.flags & (kHardlinkDup | kExcluded))
        if contributes: nodes[p].size += n.size; nodes[p].alloc += n.alloc   (saturating)
        if n.flags & kDir and !(n.flags & kExcluded):
            counts[p].dirs  += 1 + counts[id].dirs
            counts[p].files += counts[id].files
        else if !(n.flags & kExcluded):
            counts[p].files += 1                 # hard-link duplicates are still entries
```

O(n), reverse sequential access; 10M nodes ≈ 30–60 ms. During a scan, `aggregate_partial()` runs at most once per second (skipped if the previous run took > 20% of the interval). `mark_deleted` walks the parent chain subtracting (O(depth)).

#### 2.4.2 Walk-mode algorithm (single-writer design)

One **builder thread** owns `TreeBuilder` and dispatches work; **N workers** only do I/O.

```text
start_scan(opts):
    validate targets (exist, absolute, de-duplicate, reject nesting) → builder = TreeBuilder(roots)
    jobs = WorkQueue<Job{dir_id, path, dev, depth}>; results = BoundedQueue<DirResult>(4 * N)
    push one job per root; pending = #roots; start N workers + builder; return handle

worker:  while !cancelled: wait while paused; job = jobs.pop_or_wait(5ms); if none and pending==0: exit
         listing = backend.read_dir(job.path, hint(job)); results.push({job, listing})   # blocks ⇒ backpressure

builder: for {job, listing} in results:
    new_nodes = []; subdirs = []
    for e in listing.entries:
        if excluded(e, job.path): continue
        flags = flags_from(e)
        if e.kind == File and hardlinks == Dedup and e.nlink != 1:      # Windows walk: nlink 0 ⇒ always check
            if !seen.insert((e.dev, e.ino_hi, e.ino_lo)): flags |= kHardlinkDup
        if e.kind == Dir:
            if e.dev != job.dev and !cross_filesystems: flags |= kMountPoint   # not descended
            else subdirs.push(index)
        if e.kind in (Symlink, Junction) and follow_symlinks:
            t = backend.stat_follow(...); if t is dir and visited_dirs.insert(t.id): subdirs.push(index)
            else if t is dir: issue SymlinkLoop
        new_nodes.push(...)
    range = builder.add_children(job.dir_id, new_nodes)                  # contiguity guaranteed
    if listing.partial: mark kPartial; failed listing ⇒ mark kAccessDenied (or kError), size 0
    for i in subdirs: jobs.push({range.first + i, join(job.path, name), dev}); pending++
    pending--; update atomics; maybe aggregate_partial(); if pending == 0: break
    tree = builder.finish(meta); if owner == Eager: resolve owners (parallel lookups, single insertion)
```

Cancellation: workers stop; builder drains results, marks dirs with pending jobs `kPartial`, finishes with `meta.cancelled = true`. Pause: workers block between directories. Files vanishing between listing and stat are skipped (`NotFound`).

#### 2.4.3 Windows MFT fast mode (pseudocode)

Lives in `core/src/platform/windows/mft_reader.cpp` (volume I/O) + `core/src/mft/` (pure parser, compiled and unit-tested on all OSes with golden byte fixtures).

```text
mft_scan(volume_root "C:\\", opts, sink):
    if !is_elevated(): fail("not elevated")
    h = CreateFileW(L"\\\\.\\C:", GENERIC_READ, FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE, OPEN_EXISTING)  # denied ⇒ fail
    vd = DeviceIoControl(h, FSCTL_GET_NTFS_VOLUME_DATA)          # not NTFS ⇒ fail("not NTFS")
    rec_size = vd.BytesPerFileRecordSegment (1024 typical); cluster = vd.BytesPerCluster
    total = vd.MftValidDataLength / rec_size                     # progress denominator
    rec0 = read(vd.MftStartLcn * cluster, rec_size); apply_fixups(rec0)
    runs = decode_runlist(unnamed $DATA of rec0)                 # follow $ATTRIBUTE_LIST if present
    reader thread: read 8 MiB sector-aligned chunks along `runs` → bounded queue (4 chunks)
    parser pool (std::thread × cores): for each record slice i in chunk:
        signature "FILE" else skip (BAAD ⇒ issue); apply_fixups or skip with issue
        if !(flags & IN_USE): skip
        target = base_record_ref & 0xFFFFFFFFFFFF ? base : i        # extension records merge into base
        for attr in attributes(slice):                              # every offset/length bounds-checked
            0x10 STANDARD_INFORMATION → times (FILETIME→unix), attributes (hidden/system/sparse/compressed/reparse)
            0x30 FILE_NAME → (parent_ref, namespace, UTF-16 name); skip DOS-only names when a Win32 name exists for same parent
                             several FILE_NAMEs with different parents = hard links
            0x80 DATA unnamed: resident ⇒ size = value_len, alloc = 0
                               non-resident & lowest_vcn == 0 ⇒ size = data_size, alloc = compressed|sparse ? total_allocated : allocated_size
            0x80 DATA named (ADS) ⇒ add to size/alloc only if include_ads
        merge into per-thread partial index; merge partial indices (disjoint record numbers)
    build tree: root = record 5
        link (parent_idx → child) for each name; parent not in use or sequence mismatch ⇒ orphan (issue Orphaned, skipped)
        children lists via counting sort by parent (two passes, O(n))
        BFS from record 5 assigning NodeIds ⇒ parents before children, children contiguous
        multi-link records: first visited link counts, others kHardlinkDup
        NTFS metafiles (records 0–15, $Extend subtree) included as SYSTEM|HIDDEN entries under the volume root
            (they use real space; $MFT can be GBs). show_ntfs_metafiles=false omits them (documented).
        target is a subfolder ⇒ build volume tree, extract the subtree (re-index into a new Tree)
```

**Auto-mode policy:** use MFT iff the target is a local NTFS volume root (or depth ≤ 1), the process is elevated, and `follow_symlinks == false`. Any failure before the first record ⇒ `Notice::FastModeUnavailable{reason}` and a transparent walk scan; failure mid-way ⇒ discard, notice, walk. `ScanMode::Mft` never falls back (raises `MftUnavailable`). Parser functions return `Expected<T, MftError>` and never throw on malformed input; fuzzed nightly.

- Sorting sorts a `std::vector<NodeId>` of a directory's children (arena never reordered); cached per `(dir, key, desc)` in an LRU of 256 entries. Name sort = natural order (`file2 < file10`), case-insensitive with simple Unicode case folding.
- Filtering: `FilterSpec` matches files; a directory row is visible iff it or a descendant matches. The visible set is computed once per filter change in a parallel pass into a bitset.

`FilterSpec` (built by the Python query parser, §2.8; evaluated in C++):

```cpp
struct Cmp64 { enum Op : std::uint8_t { Lt, Le, Eq, Ge, Gt } op; std::uint64_t v; };
struct FilterSpec {                           // expression tree, evaluated cheapest-first
    enum class Kind : std::uint8_t { And, Or, Not, Size, Alloc, Ext, NameGlob, PathGlob, Regex, Owner, Time, Type, Files, Flag };
    Kind kind; std::vector<FilterSpec> children;              // And/Or/Not
    Cmp64 cmp{}; TimeField time_field{}; std::vector<std::string> values; // exts, globs, owners
    std::string regex;                                          // PCRE2 pattern (UTF mode, case-insensitive default, 1 MiB compile limit)
    std::uint16_t flag = 0; bool type_dir = false;
};
```

Evaluation order inside `And`: flags/type → size/alloc → ext → time → globs → regex → owner (owner forces lazy resolution only for candidates that passed everything else).

### 2.6 Threading model

| Thread / pool                     | Count                                                                                        | Purpose                                                                                                     |
| --------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Scan workers (C++ `std::jthread`) | auto: local SSD → `min(2×logical CPUs, 32)`; HDD (rotational) → 2; network FS → 16; SFTP → 8 | `read_dir` only                                                                                             |
| Scan builder (C++)                | 1                                                                                            | owns `TreeBuilder`, dispatches jobs                                                                         |
| MFT reader + parsers (C++)        | 1 + logical CPUs                                                                             | sequential volume reads, parallel record parsing                                                            |
| Analysis pool (C++)               | logical CPUs (shared `ThreadPool` singleton)                                                 | filtering, top-N, stats, layout                                                                             |
| Hashing (C++, duplicates)         | SSD `min(CPUs, 8)`; HDD 1 (files sorted by `(dev, inode)`); network 4                        | read + hash                                                                                                 |
| Python main thread                | 1                                                                                            | Qt event loop / CLI                                                                                         |
| Qt `QThreadPool` workers (Python) | ≤ 4                                                                                          | wrap blocking `_core` calls (find, dupes, export, snapshot I/O) so the UI never blocks; results via signals |

GIL policy: every binding that can take > 1 ms releases the GIL (`nb::call_guard<nb::gil_scoped_release>`); C++ never calls back into Python from non-Python threads. Shared trees are `std::shared_ptr<const Tree>`; mutations (owner resolution, delete updates, subtree replace) go through `TreeHandle` which holds a `std::shared_mutex` (readers: views/analysis; writer: mutations).

### 2.8 Query language (Python parser → C++ `FilterSpec`)

Grammar (case-insensitive keywords; whitespace = AND; `OR` keyword; `-` prefix = NOT; parentheses):

```
query   := or_expr
or_expr := and_expr ("OR" and_expr)*
and_expr:= unary+
unary   := "-"? atom
atom    := "(" or_expr ")" | term
term    := field op value | bare_word
field   := size | alloc | ext | name | path | regex | owner | modified | created | accessed | type | files | flag
op      := ">" | ">=" | "<" | "<=" | "=" | ":"
value   := number unit? | duration | date | word | "quoted string" | v1,v2,...   (comma = OR within field)
unit    := B | KB | MB | GB | TB | KiB | MiB | GiB | TiB   (KB = 1024 per A4 unless --si)
duration:= number (d|w|m|y)   e.g. modified>1y = older than one year; modified<7d = newer than 7 days
date    := YYYY-MM-DD (local midnight)
bare_word → name glob "*word*"
```

Examples: `size>1GB ext:iso,img`, `modified>2y -path:*/node_modules/*`, `regex:"^IMG_\d{4}\.jpe?g$" owner:ahmed`, `type:dir files=0`, `flag:hardlink`.

Rows are fetched in pages of 200 via one `view.rows()` call and kept in an LRU of 50 pages. `data()` handles only `DisplayRole`, `ToolTipRole`, `AccessibleTextRole`, `UserRole` (row tuple); everything else returns `None` immediately (measured 3× speed-up).
- **TreeTableView(QTableView)**: vertical header hidden, fixed row height (24 px, 28 px "comfortable"), `setUniformRowHeights`-equivalent via fixed section size, custom delegates: `NameDelegate` paints indentation, expander chevron (mirrored in RTL), type icon and elided name; `PercentDelegate` paints bar + number; `SizeDelegate` formats with the active unit mode (format cache per row page). Expand/collapse call `beginInsertRows/endInsertRows` with counts returned from C++.
- **TreemapWidget(QWidget)**: requests `treemap_layout` + `treemap_render` in a worker (debounced 150 ms on resize), shows the RGBA buffer as `QImage` (buffer reference kept alive), hit-tests with `layout.hit_test`, hover tooltip, click selects, double-click zooms, breadcrumb bar zooms out.
- **PieChart / BarChart(QWidget)**: QPainter, top 15 + "Other", keyboard-focusable slices, Okabe-Ito based colour-blind-safe palette.
- **Polling**: `ScanController(QObject)` owns the `ScanHandle`, polls every 250 ms, emits `progressChanged`, `issuesAdded`, `noticeReceived`, `finished` signals.
- **Theme**: Fusion style with light/dark `QPalette` + small QSS for bars/treemap colours; `System` follows `QGuiApplication.styleHints().colorScheme()` live.
- **RTL**: `QGuiApplication.setLayoutDirection(Qt.RightToLeft)` for RTL locales; delegates use `QStyle.visualRect`/`option.direction`.
- **Accessibility**: every action has text + accessible name; custom widgets register `QAccessibleInterface` subclasses (role, name, value, child rects) — treemap exposes its top 50 rects as children; charts expose slices.

### 2.12 Duplicate finder (C++, `core/src/analysis/dupes/`)

```cpp
enum class HashAlgo { Blake3, Xxh3_128, Sha256 };              // default Blake3
struct DupOptions { std::uint64_t min_size = 1 << 20; std::optional<std::uint64_t> max_size; HashAlgo algo = HashAlgo::Blake3;
                    std::uint32_t partial_bytes = 16 * 1024; bool include_hidden = false, same_volume_only = false,
                    verify_bytes = false; unsigned io_threads = 0; std::optional<FilterSpec> filter; };
struct DupGroup { std::uint64_t size; std::array<std::uint8_t, 32> hash; std::vector<NodeId> files; };
struct DupReport { std::vector<DupGroup> groups; std::vector<std::vector<NodeId>> hardlink_groups;
                   std::uint64_t wasted_bytes, files_hashed, bytes_read; std::vector<std::pair<NodeId, IssueKind>> skipped; bool cancelled; };
```

Pipeline:

```text
candidates = files in subtree(scope) with size in [min,max], no {Symlink, Reparse, CloudPlaceholder, AccessDenied, Excluded}, filter matches
Stage 0: group by (dev, inode) → classes of ≥2 go to hardlink_groups (same data, no waste); keep one representative
Stage 1: group representatives by size; drop singletons
Stage 2: re-stat each file (size/mtime changed since scan ⇒ skip, IssueKind::Changed)
         size ≤ 2×partial ⇒ hash whole file (reused as full hash)
         else h = H(head partial ++ tail partial ++ size_le64); regroup by (size, h); drop singletons
Stage 3: full hash streaming, 1 MiB buffers; on HDD read in (dev, inode) order; regroup; drop singletons
Stage 4 (optional; forced before deleting duplicates): byte-compare each member to the first; split on mismatch
wasted = Σ size × (len(group) − 1)
```

Files opened read-only with full sharing (`FILE_SHARE_READ|WRITE|DELETE`), `O_NOATIME` when permitted (retry without on `EPERM`). Cancellation checked between files and every 8 MiB. Python helper `dafree.api.auto_select(group, rule)` with `KeepRule ∈ {OLDEST, NEWEST, SHORTEST_PATH, LONGEST_PATH, IN_FOLDER(p), NOT_IN_FOLDER(p)}` **never returns every member** (raises `ValueError` instead).

### 2.13 Snapshots and comparison (C++, `core/src/io/snapshot.cpp`, `core/src/analysis/diff.cpp`)

File format `.dafsnap` v1 (documented in `docs/reference/snapshot-format.md`):

```
offset 0  magic   "DAFSNAP\0" (8 bytes)
offset 8  u32 LE  format_version = 1
offset 12 u32 LE  flags (bit0 = zstd, always 1 in v1)
offset 16 u32 LE  header_len
offset 20 header  JSON (UTF-8): { app_version, created_at, host, os, root_paths, node_count, name_encoding: "posix-bytes"|"wtf8", meta }
then      zstd stream (level 3, long-distance matching) of length-prefixed (u64 LE) sections:
          1 nodes  : Node records, 56 B each, little-endian field-by-field (no memcpy of structs → endian-safe)
          2 counts : Counts records
          3 names  : concatenated name bytes
          4 exts   : u32 count + length-prefixed strings
          5 owners : u32 count + length-prefixed strings
end       u32 LE  CRC32C of all preceding bytes
```

Readers reject unknown major versions, ignore unknown header keys. Loading a snapshot from another OS family converts names with lossy fallback and sets `meta.foreign_names`. Targets: 1M nodes ≤ 25 MB, save ≤ 1.5 s, load ≤ 1.5 s.

Diff (match by path; merge-join on name-sorted children):

```text
pair roots by identical root path (unmatched ⇒ Added/Removed)
stack = [(old_root, new_root)]
while stack: (o, n) = pop
    emit DiffNode{name, old/new size, alloc, files, status ∈ {Added, Removed, Grown, Shrunk, Unchanged}}
    if both dirs and depth < max_depth and !(prune_unchanged and unchanged):
        a, b = children sorted by name (case-insensitive if new tree's meta.os is Windows/macOS)
        merge-join: equal ⇒ push (ca, cb); only old ⇒ (ca, ∅); only new ⇒ (∅, cb)
DiffTree stores nodes in its own arena (contiguous children, int64 deltas); exposed via DiffView (same paging API as TreeView)
```

Invariant (property-tested): Σ delta(children) == delta(dir) whenever no hard-link/excluded differences exist.

### 2.14 Treemap (C++, `core/src/viz/`)

Squarified layout (Bruls, Huizing & van Wijk 2000) + cushion shading (van Wijk & van de Wetering 1999) rendered in C++ into an RGBA buffer.

```text
layout(tree, root, rect, opts{max_depth 12, min_px 3, max_rects 50_000, padding 1, header_px 0|14}):
    out = []; queue = [(root, rect, 0)]                      # BFS so the budget favours large items
    while queue and len(out) < max_rects:
        (id, r, d) = pop_front; out.push({r, id, d, class(id)})
        if !dir or d == max_depth: continue
        inner = shrink(r, padding, header_px if d > 0)
        kids = children with size > 0 and !HardlinkDup, sorted by size desc
        if area(inner) < min_px²: continue
        rows = squarify(kids, inner)                         # add to row while worst aspect ratio improves
        items smaller than min_px² merged into one "N small items" rect (flag OTHER)
        queue.extend(rects with d+1)
render(layout, palette, cushion): per rect accumulate cushion coefficients down the hierarchy;
    shade each pixel I = ambient + max(0, n·L) with light L=(1,2,10)/|L|; flat mode fills colour only.
class(id): dirs by depth; files by extension category (Image, Video, Audio, Archive, Document, Code, Executable, DiskImage, System, Other)
hit_test(x, y): uniform grid index (32 px cells) built with the layout → smallest containing rect
```

Rects exported as NumPy structured array `[x f4, y f4, w f4, h f4, node u4, depth u1, cls u1, flags u1, pad u1]` (24 B). Properties tested: nesting, no sibling overlap (ε = 0.01 px), area ∝ size within 1%, ≤ max_rects.

### 2.15 Delete / move safety model (Python orchestration `dafree.actions`, C++ low-level removal)

```python
class DeleteMode(Enum): TRASH = "trash"; PERMANENT = "permanent"
class BlockReason(Enum): PROTECTED_PATH, VOLUME_ROOT, OUTSIDE_SCAN_ROOTS, ANCESTOR_SELECTED, CHANGED_SINCE_SCAN,
                         MISSING, TRASH_UNAVAILABLE, IS_MOUNT_POINT, INSIDE_MOUNT_POINT, IS_SNAPSHOT
@dataclass(frozen=True) class PlanItem: node: int; path: str; kind: EntryKind; size: int; dev: int; ino: tuple[int, int]; mtime: int
@dataclass(frozen=True) class DeletePlan: id: int; mode: DeleteMode; items: tuple[PlanItem, ...]; blocked: tuple[tuple[str, BlockReason], ...]
                                         total_size: int; total_files: int; confirm_token: str; created_at: float
def plan_delete(tree: TreeHandle, nodes: Sequence[int], mode: DeleteMode, protect: ProtectedPaths) -> DeletePlan
def execute_delete(plan: DeletePlan, confirm_token: str, *, dry_run: bool, progress: Callable[[ActionProgress], None] | None = None) -> ActionReport
def plan_move(tree, nodes, dest: Path, protect) -> MovePlan
def execute_move(plan: MovePlan, confirm_token: str, *, dry_run: bool, overwrite: bool = False, verify: bool = True, progress=None) -> ActionReport
```

Rules (each has a dedicated test):

1. Nothing executes without a plan and its exact `confirm_token` (`secrets.token_hex(8)`); tokens expire after 10 minutes and are single-use. Snapshot-backed trees cannot produce plans (`IS_SNAPSHOT`).
2. If a folder and something inside it are both selected, only the folder stays (`ANCESTOR_SELECTED`).
3. Immediately before acting on each item, re-`lstat` (`os.lstat`, no following): missing ⇒ `MISSING`; `(dev, ino)` or type changed, or for files size/mtime changed ⇒ `CHANGED_SINCE_SCAN` (skipped, reported).
4. Links are removed as links, never traversed. Permanent recursive deletion uses C++ `platform::remove_tree_nofollow`: POSIX iterative post-order with `openat(O_NOFOLLOW|O_DIRECTORY)` / `unlinkat` / `unlinkat(AT_REMOVEDIR)`; Windows handle-based with `FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS` and `FileDispositionInfoEx` (POSIX semantics + ignore read-only); never crosses mount points (that subtree reported `INSIDE_MOUNT_POINT`). `shutil.rmtree` is **forbidden** in the codebase (ruff banned-api rule).
5. Protected paths (never deletable): volume roots (`C:\`, `/`), the user's home directory itself, `%WINDIR%`, `%ProgramFiles%`, `%ProgramFiles(x86)%`, `%ProgramData%`, `/System`, `/usr`, `/bin`, `/sbin`, `/etc`, `/lib*`, `/boot`, `/Library`, `/Applications` (the folder itself), the app's own install/portable directory, and anything outside the scan roots.
6. Trash mode uses Send2Trash; if the volume has no trash (network share, some removable media), items are `TRASH_UNAVAILABLE` and the UI must offer permanent deletion as a separate explicit choice.
7. `dry_run=True` performs every check including the re-stat and returns the report without modifying anything.
8. After execution the tree is updated (`mark_deleted` ⇒ `kExcluded` + incremental re-aggregation); views refresh.
9. Move: same volume ⇒ `os.rename`; cross-volume ⇒ copy (1 MiB buffers, preserve mtime and read-only bit) + verify size (+ BLAKE3 via `_core.hash_file` when `verify`) + delete source; on failure the partial destination is removed. Destination conflicts ⇒ skipped unless `overwrite=True` (never default).

**Exit codes** (`src/dafree/cli/exit_codes.py`, documented in `docs/reference/exit-codes.md`):

| Code | Meaning                                                                                  |
| ---- | ---------------------------------------------------------------------------------------- |
| 0    | Success                                                                                  |
| 1    | Runtime error (I/O on target, bad snapshot, …)                                           |
| 2    | Usage error                                                                              |
| 3    | Alert threshold exceeded (`schedule run`, `scan --alert`)                                |
| 4    | Completed with access errors (only with `--strict`)                                      |
| 5    | Results found where none were expected (`--fail-if-found`)                               |
| 10   | Action blocked by safety checks (some items blocked/changed; nothing unsafe done)        |
| 130  | Interrupted (Ctrl+C) — partial output flushed; JSON stays valid with `"cancelled": true` |

Machine formats write only data to stdout; progress/warnings/errors go to stderr. JSON/NDJSON/CSV are never localized. Table output honours `NO_COLOR` and `--no-color`.

## 6. Testing strategy

### 6.1 Test layers

| Layer                                  | Tooling                                                                  | Location                                                  | Runs in                                                         |
| -------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------- | --------------------------------------------------------------- |
| C++ unit tests                         | doctest via `ctest`                                                      | `core/tests/`                                             | `ci.yml` cpp matrix (3 OSes)                                    |
| C++ sanitizers                         | ASan + UBSan (clang, Linux), TSan (scanner/dupes/view tests)             | same tests + Python suite under ASan                      | `ci.yml` sanitizers job                                         |
| C++ static analysis                    | clang-tidy (Linux), MSVC `/analyze` (Windows, nightly)                   | `core/`, `bindings/`                                      | `ci.yml` cpp (Linux), `nightly.yml`                             |
| C++ benchmarks                         | Google Benchmark JSON                                                    | `core/bench/`                                             | `ci.yml` bench (PR vs base), `nightly.yml` absolute             |
| Fuzzing                                | libFuzzer + ASan/UBSan                                                   | `core/fuzz/` (mft_record, runlist, snapshot_reader, glob) | `nightly.yml` (300 s/target)                                    |
| Python unit                            | pytest                                                                   | `tests/unit/`                                             | `ci.yml` python matrix                                          |
| Python property                        | Hypothesis (`max_examples=1000` in CI profile, 10,000 nightly)           | `tests/property/`                                         | `ci.yml`, `nightly.yml`                                         |
| Integration (real FS through bindings) | pytest + `tests/testkit` fixtures + oracle                               | `tests/integration/`                                      | `ci.yml` python matrix (3 OSes)                                 |
| CLI                                    | click `CliRunner` + subprocess, syrupy snapshots, jsonschema             | `tests/cli/`                                              | `ci.yml` python matrix                                          |
| GUI                                    | pytest-qt, `QT_QPA_PLATFORM=offscreen`, `QAbstractItemModelTester`       | `tests/gui/`                                              | `ci.yml` python matrix (3 OSes)                                 |
| Accessibility                          | pytest-qt checks on `QAccessible` interfaces, names, tab order, contrast | `tests/gui/test_accessibility.py`                         | `ci.yml`                                                        |
| Frozen-app e2e                         | `--self-test` against PyInstaller bundle                                 | `tests/e2e/`                                              | `ci.yml` (Linux), `release.yml` + `nightly.yml` (all OSes)      |
| Performance & memory                   | pytest perf markers + C++ counting allocator                             | `tests/perf/`, `core/tests/test_memory.cpp`               | `ci.yml` (memory, scroll on Linux), `nightly.yml` (all targets) |
| Wheel tests                            | cibuildwheel `test-command` inside each built wheel                      | `tests/unit`, `tests/integration` subset                  | `ci.yml` wheels, `release.yml`                                  |

Rules: **no retries** for flaky tests (fix the cause); env-gated tests must be enabled in CI (`DAFREE_REQUIRE_ALL_CAPS=1`, `DAFREE_REQUIRE_GUI=1`, `DAFREE_TEST_MOUNTS=1` on Linux, `DAFREE_TEST_SCHEDULER=1`, `DAFREE_TEST_SMB=1` on the Linux leg), so a silent skip in CI is impossible.

### 6.2 Fixture catalogue (generated at test time; only golden MFT records are committed)

| Preset                   | Contents                                                                                                               | Purpose                                      |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `small_mixed`            | ~60 entries, 4 levels, 0 B–5 MB files, hidden and read-only files                                                      | CLI snapshots, GUI tests                     |
| `unicode_zoo`            | Arabic, CJK, emoji, combining marks, NFC/NFD twins (Linux), spaces, leading dash, 255-byte name, invalid UTF-8 (Linux) | path round-trip, display, export escaping    |
| `symlink_loop`           | `a/b/link → ../..`, `self → .`, dangling link, link to file, link to dir outside fixture                               | loop safety, follow/no-follow, delete safety |
| `hardlinks`              | 10 MB file with 3 links across dirs; 1 KB file with 2 links in the same dir                                            | dedup counting, duplicates stage 0           |
| `deep(300)`              | 300 nested dirs                                                                                                        | no recursion limits, long paths              |
| `long_paths`             | path ≥ 400 chars (Windows) / ≥ 4,200 bytes (Linux)                                                                     | verbatim paths, `openat` walking             |
| `wide(100_000)`          | 100k files in one dir                                                                                                  | huge folders, view expand                    |
| `sparse_big`             | 1 GiB sparse file with 4 KiB written at 512 MiB                                                                        | size vs allocated                            |
| `permission_denied`      | unreadable dir with files; unreadable single file                                                                      | issue reporting, totals continue             |
| `mounts` (Linux)         | tmpfs mounted inside the fixture                                                                                       | mount boundary, delete/move not crossing     |
| `dupes_mix`              | identical files, same size different content, same head+tail different middle, zero-byte files, hard links             | duplicate pipeline                           |
| `ci_500k` / `1m` / `10m` | generated by `tools/gen_fixtures.py`                                                                                   | benchmarks                                   |

Integration tests assert against the **oracle** computed from the spec; `small_mixed` additionally has a hand-verified expected table to catch oracle bugs. C++ unit tests use their own tiny temp-dir builders or the MockBackend; C++ never depends on the Python testkit.

### 6.3 Cross-checks

- Walk vs MFT on the same NTFS subtree (Windows CI): identical names, sizes, counts, hard-link classification; resident-file allocated-size relation asserted.
- `load(save(tree))` identical (property, C++ and Python).
- CLI JSON vs API values (`test_cli_json_matches_api`).
- GUI and CLI analysis data come from the same C++ functions (asserted by tests that call both paths on one tree).
- Python reference implementations (NumPy over `Tree.arrays()`) vs C++ for aggregation, top-N, ext/age stats and find on random trees (Hypothesis).

### 6.4 Property-based tests (minimum set)

| Property                                                                             | Where                                                |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| SegVector ≡ std::vector under random ops                                             | doctest (seeded)                                     |
| Random builds keep `parent < child` and contiguity                                   | doctest + Hypothesis via `_core.testing.TreeBuilder` |
| Aggregation equals recursive/NumPy oracle; `mark_deleted` equals full re-aggregation | doctest + Hypothesis                                 |
| `TreeView` rows ≡ naive flatten+sort under random expand/collapse/sort               | Hypothesis (Python oracle)                           |
| Query `parse(str(q)) == q`; `find` ≡ Python filter                                   | Hypothesis                                           |
| Units `parse(format(x))` within rounding                                             | doctest                                              |
| Treemap nesting, non-overlap, area proportionality                                   | doctest                                              |
| Snapshot round-trip                                                                  | doctest + Hypothesis                                 |
| Diff: identical ⇒ unchanged; child deltas sum to parent                              | doctest                                              |
| Duplicates ≡ content-equality oracle; auto-select never selects all                  | doctest + Hypothesis                                 |
| Run-list encode/decode; random MFT index invariants                                  | doctest                                              |
| Cron next runs ≡ brute force                                                         | Hypothesis                                           |

### 6.6 Fuzzing

Targets `fuzz_mft_record`, `fuzz_runlist`, `fuzz_snapshot_reader`, `fuzz_glob`; nightly 300 s each with `-rss_limit_mb=2048 -timeout=10`; corpus cached between runs; crashes uploaded as artifacts and an issue opened automatically; every crash becomes a doctest regression case.

## 7. GitHub Actions CI/CD

### 7.1 Workflows

| Workflow      | Trigger                            | Purpose                                                                                                                                                             |
| ------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ci.yml`      | push to `main`, PRs, `merge_group` | lint, C++ build/test, sanitizers, Python tests (3 OSes × versions), coverage, wheels, frozen smoke, audit, docs, PR benchmarks; single required check `ci-success`  |
| `release.yml` | tag `v*.*.*`, manual (dry run)     | wheels + sdist (optional PyPI), frozen installers/portable builds for all targets, smoke tests, checksums, GitHub Release                                           |
| `nightly.yml` | cron `0 2 * * *`, manual           | fuzzing, 10k-example property tests, absolute perf targets on 3 OSes, MSVC `/analyze`, frozen e2e on all OSes, portable-mode e2e; opens/updates an issue on failure |
| `codeql.yml`  | push/PR to `main`, weekly          | CodeQL `python`, `c-cpp` (manual build via CMake preset), `actions`                                                                                                 |
| `docs.yml`    | push to `main`                     | build MkDocs and deploy to GitHub Pages                                                                                                                             |

### 7.2 Caching and failure reporting

- pip: `actions/setup-python` `cache: pip` keyed on `requirements/*.txt` + `pyproject.toml`.
- C++ compilation: `hendrikmuhs/ccache-action` (ccache on Linux/macOS, sccache on Windows) with keys per job/OS; CMake `FETCHCONTENT_BASE_DIR=.deps` cached with `actions/cache` keyed on `hashFiles('cmake/Dependencies.cmake')`.
- scikit-build-core build dir (`build/{wheel_tag}`) cached per OS for Python test jobs (`actions/cache`, key on C++ sources hash) — speeds up `pip install .`.
- Failure reporting: (1) every job appends a Markdown summary to `$GITHUB_STEP_SUMMARY` (failing tests from JUnit via `tools/junit_summary.py`, benchmark tables, coverage); (2) JUnit XML, syrupy `.ambr` diffs, Qt screenshots on GUI test failure (`tests/gui/conftest.py` saves `QWidget.grab()` PNGs) and sanitizer logs uploaded as artifacts (14 days); (3) `ci-success` aggregates all jobs for branch protection; (4) nightly failures open/update one issue labelled `ci-nightly-failure`.

### 8.6 License: MIT, plus the Qt LGPL obligations

The product owner chose **MIT**:

- Permissive and short → lowest barrier for contributors, packagers (winget, Homebrew, distro repos) and companies; compatible with the chosen permissive dependencies.
- Trade-off acknowledged: MIT allows closed-source forks and has no explicit patent grant. Accepted; recorded in `DECISIONS.md`.
- **Qt/PySide6 are LGPL-3.0.** The project's own code stays MIT. Distributing frozen apps that bundle Qt is permitted under LGPL when: (a) Qt/PySide6/shiboken6 are shipped as separate, replaceable shared libraries (PyInstaller onedir — never statically linked or merged into a single-file exe), (b) the LGPL-3.0 and GPL-3.0 texts plus a notice naming the Qt/PySide6 versions and pointing to their source (`https://download.qt.io/official_releases/`, `https://code.qt.io/`) are included in the app (`licenses/` folder in bundles, About dialog link) and in `THIRD_PARTY_LICENSES.md`, (c) users are not prevented from replacing those libraries (no signature checks on them by our code; macOS notarized bundles document that replacing libraries breaks the signature, which is acceptable). The pip wheel does not bundle Qt at all (PySide6 is a separate dependency).
- Consequences enforced in CI: runtime license allowlist with exactly one named LGPL exception (PySide6-Essentials, shiboken6); GPL-only Qt modules (Charts, Data Visualization, Graphs, Virtual Keyboard, …) are not in Essentials and must never be added (checked by `tools/check_lgpl_exception.py`, which also scans the frozen bundle for forbidden Qt module files).

## 9. Risk register

| #   | Risk                                                                                                                   | Likelihood | Impact   | Mitigation                                                                                                                                                                                                                                               |
| --- | ---------------------------------------------------------------------------------------------------------------------- | ---------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | MFT access unavailable (not elevated, BitLocker-locked, ReFS/FAT/exFAT, Dev Drive, network)                            | High       | Medium   | Auto mode with transparent walk fallback + notice; "Restart as administrator"; Windows walk uses batched `FileIdExtdDirectoryInfo` (no per-file opens).                                                                                                  |
| R2  | MFT parser bugs / malformed records crash the process (C++ memory safety)                                              | Medium     | High     | Bounds-checked `ByteReader`, `Expected<>` returns, no raw pointer arithmetic outside the reader; golden tests; ASan/UBSan in CI; libFuzzer nightly; walk-vs-MFT cross-check on Windows CI; failure → fallback.                                           |
| R3  | Memory blow-up on huge trees                                                                                           | Medium     | High     | 56-byte nodes in segmented arrays, name arena, no per-node Python objects, counting-allocator budget tests, memory report in the About/Diagnostics dialog.                                                                                               |
| R4  | GIL contention or deadlocks between Qt, Python and C++ threads                                                         | Medium     | High     | C++ never calls into Python from its threads; all long calls release the GIL; GUI polls via `QTimer`; TSan on C++; pytest-timeout on every test; a dedicated test asserts the GIL is released during `wait()`.                                           |
| R5  | GUI sluggish with millions of rows (Python per-cell overhead)                                                          | Medium     | High     | Measured design: page fetch of 200 rows per C++ call, minimal roles, custom delegates (15 ms median / 22 ms p95 at 10M rows); perf test in CI; treemap rendered to a pixel buffer in C++.                                                                |

## 11. Agent working instructions

1. **Work milestone by milestone, task by task, in order.** A task starts only when its dependencies are done; M3 may run in parallel with M2.
2. **One task = one branch = one PR** (`agent/m<N>-t<id>-<slug>`), squash-merged when `ci-success` is green. Split tasks whose diff exceeds ~800 changed lines (excluding generated files and snapshots).
3. **After every task, run locally:** `ruff check . && ruff format --check . && mypy`, `cmake --preset dev && cmake --build --preset dev && ctest --preset dev`, `pip install -e ".[gui]"` (or `pip install .`) then `pytest -m "not slow"`; regenerate stubs (`python tools/gen_stubs.py`) after any binding change; run `tools/i18n_check.py` after UI string changes. Fix everything before pushing.
4. **Never skip, ignore, delete or weaken a failing test** to make CI pass. No `pytest.mark.skip`/`xfail` or doctest `skip` without an env-gated reason; no lowering of coverage/perf thresholds without a `DECISIONS.md` entry. No test retries.
5. **Conventional Commits** for every commit and PR title (§8.4); reference the task in the body (`Task: T1.11`).
6. **Do not ask questions.** When something is unspecified, choose the most conservative reasonable option, implement it, and append to `DECISIONS.md`:
   ```
   ## D-0042 — 2026-11-03 — Short title
   Context: …  Decision: …  Alternatives: …  Consequences: …  Task: T6.4
   ```
7. **Respect boundaries:** OS calls only in `core/src/platform`; only `dafree.api` imports `_core`; the GUI never blocks the event loop (use `TaskRunner`); C++ never calls Python from worker threads; no `shutil.rmtree`; no raw `new/delete` in C++ (RAII only); parser code returns errors instead of throwing on malformed input.
8. **Safety first for destructive code:** any change to `dafree.actions` or `remove_tree_*` adds/updates tests for every affected rule in §2.15 and keeps the link-escape tests passing on all three OSes.
9. **Public contracts are versioned:** CLI flags/exit codes, JSON schema, snapshot format and `dafree.api` changes update docs, schema and snapshot tests in the same PR.
10. **Keep generated files in sync:** `_core.pyi`, `dafree.pot`, CLI docs, `THIRD_PARTY_LICENSES.md`, requirement lock files.
11. **Licensing:** add only dependencies allowed by §1.3 policy (the only LGPL exception is PySide6-Essentials/shiboken6). Never copy code, text, icons or screenshots from TreeSize or other proprietary tools; cite papers/projects for adapted algorithms.
12. **Update the checkboxes** in `docs/PLAN.md` as tasks complete.
13. **Performance changes need numbers:** PRs touching scanning, aggregation, views, treemap, hashing or the tree model include the `bench_compare.py` summary.
14. **Security hygiene:** no runtime network access except user-configured webhooks (M9) and SFTP (M11); no telemetry; subprocesses always with argument lists (never `shell=True`).
